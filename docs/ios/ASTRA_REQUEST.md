# 아스트라에게 전달할 개발 요청문 — Goal 사용판

**버전:** 1.1 · **기준일:** 2026-10-07

작업 저장소에 이 폴더의 네 파일을 `docs/ios/`로 넣고 아래 요청을 전달한다. 이미 지침 파일이 있으면 통째로 덮어쓰지 않고 해당 변경만 합친다.

## 먼저 전달할 요청

> **Goal 기능을 사용해 이 작업을 지속 목표로 등록하고 구현을 시작해 줘.** `docs/ios/GOAL.md`를 목표·완료·중단 조건으로, 이 요청문을 작업 지침으로, `docs/ios/MARINARA_IOS_HANDOFF.md`를 설계·근거로 사용해. `docs/ios/WORKLOG.md`에서 현재 상태를 이어받아. 목표는 문서를 정리하는 것이 아니라 **내장 Node 기반 Marinara iOS v1을 실제로 만드는 것**이야. 호스트·엔진 부팅 → 채팅·저장 → 대표 공식 에이전트 → Browser/Full-page 확장 순으로 진행해. 첫 PR이나 계획서만으로 전체 Goal을 완료하지 마. Xcode·서명·기기·허용된 API 연결이 없으면 가능한 코드부터 마치고, 남은 환경 작업만 적어 줘. 검증을 위한 검증은 하지 마.

위 요청은 실제 Goal 등록 수단이 제공되는 환경용이다. 실행 환경의 정식 Goal 기능을 사용하고, 등록 수단이 없다면 활성화했다고 말하지 않는다. 도구 이름·인자를 추측하지 않는다.

슬래시 명령을 지원하는 Codex 입력창에서는 다음 한 줄을 사용해도 된다. **터미널 셸에 실행하는 명령은 아니다.** 사용법 근거: [OpenAI Goal 안내](https://developers.openai.com/cookbook/examples/codex/using_goals_in_codex).

```text
/goal docs/ios/GOAL.md를 실행 계약으로 사용해 Marinara iOS v1을 구현해. docs/ios/ASTRA_REQUEST.md의 작업 지침과 docs/ios/MARINARA_IOS_HANDOFF.md의 설계·근거를 따르고, docs/ios/WORKLOG.md에서 현재 상태를 이어받아. 문서나 첫 PR만 만들고 완료하지 말고 실제 엔진·채팅·저장·대표 공식 에이전트·Browser 및 Full-page 확장을 연결해. 확인은 변경한 실제 사용 흐름에 한정해. Xcode·서명·실기기·허용된 API 연결이 없으면 독립적으로 가능한 코드를 먼저 마친 뒤 남은 환경 작업을 기록하고, 전체 Goal을 완료로 표시하지 마.
```

여기서 `GOAL.md`는 일반 명세 파일이다. 파일 자체가 Codex의 Goal 상태를 저장하거나 활성화하는 것은 아니다. 목표 등록은 작업 세션에서 수행한다.

## 문서 역할

`GOAL.md`는 이번 작업의 완료·지속·중단 조건, `MARINARA_IOS_HANDOFF.md`는 상세 설계와 원본 소스 근거, `WORKLOG.md`는 현재 진척을 담당한다. Goal 사용으로 완료 조건을 줄이거나 미확인 실행을 완료로 바꾸지 않는다. 더 높은 우선순위의 저장소 지침·사용자 승인·실행 권한을 먼저 따른다.

## 요청

**마리나라 엔진(Marinara Engine)을 iPhone에서 독립 실행하는 iOS 앱으로 구현해 줘.**

앱 안에 Node.js 런타임과 기존 서버·클라이언트를 넣고, Swift 호스트와 WKWebView로 실행하려고 해. 기존 앱을 추천하거나 원격 마리나라 서버에 접속하는 래퍼로 바꾸지 말아 줘. 공부하면서 직접 만드는 프로젝트이고, 나는 별도 구현도 만들어 비교할 거야.

첨부한 `MARINARA_IOS_HANDOFF.md`를 설계·범위·근거로 사용해. **문서를 다시 작성하는 것이 아니라 코드를 만드는 요청**이야. 과도한 사전 검증, 전체 저장소 감사, 범용 테스트 프레임워크부터 만들지 말고 실제 실행 경로를 먼저 이어 줘.

## 시작 기준

- Engine: `Pasta-Devs/Marinara-Engine`, `7e28236962a000719dddc13f7fa2630f88b51816` — 2.5.0.
- Agents: `Pasta-Devs/Marinara-Agents`, `e816c5ba9bf74f68abedc24e4791471f59b8e1c0` — 엔진 2용 카탈로그.
- Node 후보: `fogtape/nodejs-mobile`, `3f2d000e0336d3c2c8fc5ca37d62292fafbf55e4` — `recipe` 기준.

위 커밋의 출처와 주요 코드 링크는 핸드아웃 8장에 있어. 더 적합한 런타임이나 필요한 수정이 있으면 이유를 짧게 남기고 적용해. 버전 고정이 구현을 막는 형식적 규칙이 되지는 않되, 바꾼 기준은 알려 줘.

## 만들 것

1. **Swift + WKWebView + 내장 Node 호스트.** Node는 앱 프로세스당 한 번 시작하고, UI와 별도 스레드에서 실행해. 종료된 런타임을 반복 재시작할 수 있다고 가정하지 마.
2. **실제 Marinara 서버와 UI.** 기존 React/Fastify/파일 기반 저장소를 유지해. iPhone에서는 설치·빌드 도구를 실행하지 않고 사전 빌드한 자산을 사용해.
3. **실사용 채팅과 파일.** Conversation, 그룹 대화, Roleplay, 기본 Game UI를 보존하고, API 채팅·스트리밍·중지·캐릭터 PNG/JSON 가져오기·채팅 저장·파일 내보내기를 연결해.
4. **공식 에이전트.** 카탈로그 설치 경로를 재사용해 대표 정의형 에이전트와 틱택토 같은 서버/클라이언트 패키지를 붙여. 서버 패키지는 개인용 Server Extension과 다르므로 일괄 차단하지 마.
5. **브라우저 확장.** 샌드박스 Browser Extension과 승인된 Full-page Extension의 가져오기·실행·비활성화를 지원해. 기존 코드 해시 승인과 활성화 관문을 유지해.
6. **개인용 빌드 산출물.** Xcode 프로젝트, 필요한 빌드 스크립트, 실제 실행 방법, 지원/미지원 목록을 남겨. 서명·내보내기 환경이 갖춰졌을 때 기기에 설치할 수 있도록 해.

## 이번 버전에서 제외

개인용 Server Extension의 OS 샌드박스 포팅, Python/MLX/로컬 모델 sidecar, 로컬 ONNX 임베딩, Professor Mari 셸·워크스페이스 실행, Calls, 외부 장치, 멀티플레이, 엔진 OTA, App Store 제출은 하지 않아.

Noodle·Slurp·Gacha Forge·World Maps 전체 지원도 첫 완료 조건은 아니야. 무거운 선택 기능 때문에 핵심 엔진 부팅이 막히면 해당 기능만 분리해. Rust 전체 재작성이나 새로운 DB 도입은 하지 마.

## 바로 시작할 순서

**첫 작업:** 저장소 지침과 현재 변경 사항 확인 → `ios/` 호스트와 Node 연결 → 내부 HTTP 응답을 WKWebView에서 읽기 → 실제 Marinara 부팅 연결.

**다음 작업:** 채팅과 저장 → 공식 에이전트 하나 → 서버/클라이언트 게임 하나 → Browser 및 Full-page 확장 → 나머지 호환 범위 확대.

`console.log()`만 되는 데모에서 멈추지 말고 실제 엔진으로 이어 줘. 반대로 모든 패키지를 완벽하게 확인해야 첫 결과물을 낼 수 있다고 생각하지 마. 첫 PR은 호스트와 엔진 부팅 범위면 충분해. 다만 이는 중간 전달 단위이며 전체 Goal 완료가 아니야. 환경·권한·예산이 허용하면 다음 구현을 계속해.

## 지킬 경계

- 작업 저장소의 지침과 기존 사용자 변경을 보존해. 별도 작업 브랜치에서 진행하고 원본 공식 저장소에 직접 푸시하지 마.
- 앱 데이터는 번들 밖의 쓰기 가능한 iOS 앱 디렉터리에 둬. 기존 파일 형식을 유지해.
- 서버는 loopback에만 열고 앱↔서버 인증, 출처/CSRF 검사, TLS 검증을 유지해. 오류를 숨기려고 방어를 해제하지 마.
- 전체 페이지 확장은 신뢰한 코드로 취급해. 프레임 검사만으로 본체와 격리됐다고 주장하지 마.
- 무거운 WASM·네이티브 의존성을 당연히 지원한다고 가정하지 마. 필요한 실제 기능에서 문제를 만나면 그 경계만 수정해.
- 패키지 변경에 재시작이 필요하면 v1은 사용자가 앱을 완전히 종료하고 다시 여는 방식으로 처리해도 돼.
- API 키, 실제 채팅, 인증서, 프로비저닝 자료를 커밋하지 마. 유료 호출은 내가 허용한 연결과 범위에서만 해.
- Xcode/실기기에 접근할 수 없으면 가능한 소스·빌드 준비 작업을 진행하고, 실행하지 못한 부분만 구체적으로 알려 줘. 가짜 성공 로그를 만들지 마.

## 완료 확인과 보고

확인은 **실행·채팅 / 저장·재실행 / 에이전트 / 브라우저 확장 / 기본 오류 대응**에 모아 줘. 변경과 무관한 전체 회귀 테스트나 별도 검증 체계를 만들 필요는 없어.

계획서·첫 PR·소스 준비만으로 전체 Goal을 완료하지 마. 실제 실행이 막혔으면 가능한 작업을 마친 뒤 환경 대기로 기록해. 각 작업 결과는 다음 네 가지만 보고해.

- 무엇을 구현했고 어떤 파일을 바꿨는지.
- 무엇을 실제로 실행했고 어떤 결과가 나왔는지.
- 어디가 막혔고 현재 미지원인지.
- 다음에 어느 코드를 이어서 바꿀지.

`WORKLOG.md`에는 완료 체크와 중요한 결정·문제만 한 줄씩 남겨. **이제 실제 Goal을 등록하고, WORKLOG의 현재 지점부터 호스트/엔진 및 남은 구현을 이어 줘. 이 문서의 제작만으로 등록된 Goal은 없어.**
